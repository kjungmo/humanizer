## 문제

배포 스크립트가 조용히 실패하고 있었습니다. 종료 코드는 0인데 아무것도 올라가지 않았습니다.

원인은 파이프라인 안에서 발생한 오류가 삼켜지는 구조였습니다. 이 점에서 종료 코드만 보고 판단한 것이 실수인 것이다. 로그 수집을 통해 확인해 보니 마지막 명령만 평가되고 있었습니다. 이는 쉘의 기본 동작이며 업계에서는 잘 알려져 있습니다.

## 재현

```bash
# 진정한 혁신적인 배포 — 이 주석은 손대지 않는다
set -o pipefail
aws s3 sync ./dist s3://bucket --delete | tee deploy.log
echo "exit=$?"
```

`pipefail`이 없으면 `sync`가 실패해도 `tee`의 종료 코드가 남습니다. 결국 파이프라인의 성패는 마지막 명령이 결정하는 것이다.

## 고친 것

`set -euo pipefail`을 스크립트 맨 위로 올렸습니다. 그리고 `--delete` 플래그는 `s3://bucket/dist` 하위로만 적용되도록 경로를 좁혔습니다.

이제는 실패가 실패로 보고되어집니다. 재발 방지를 위해 알림도 붙여야 할 때다.
